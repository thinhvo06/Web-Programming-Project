1. TỔNG QUAN PHÂN VAI (FRONT-END VS BACK-END)

THÀNH VIÊN 1: FRONT-END, UI/UX & PWA OFFLINE

  • Giao diện & Tương tác: React/Blade + Tailwind/Bootstrap; Grid/List layout; Live search debounce.
  • Auto-save: Cơ chế tự lưu ngầm không dùng nút bấm (Debounce 300-500ms).
  • WebSocket Client: Đồng bộ nội dung ghi chú thời gian thực khi cộng tác nhiều người.
  • PWA & Responsive: Service Worker + IndexedDB xem/sửa offline; Chuẩn hóa Mobile, Tablet, PC.

THÀNH VIÊN 2: BACK-END, CSDL, AI & DEVOPS

  • CSDL & API RESTful: Schema DB chuẩn; Hash Bcrypt; Phân quyền xem/sửa/xóa note.
  • Mail Service: Tích hợp SMTP gửi email kích hoạt tài khoản & mã OTP/link reset mật khẩu.
  • WebSocket Server: Socket.io server xử lý room collaboration và broadcast thay đổi.
  • AI & Triển khai: Tích hợp LLM (Gemini API) Summary/Q&A có trích dẫn; Docker Compose / Deploy HTTPS.

7. BỘ CÂU HỎI TRỌNG TÂM ÔN TẬP VẤN ĐÁP CÁ NHÂN (ORAL EXAM)
FE Q1: Làm thế nào để triển khai Auto-save mà không gây nghẽn mạng?
Trả lời: Dùng kỹ thuật Debounce (300-500ms). Mỗi khi người dùng gõ phím, reset timer. Chỉ khi dừng gõ đủ thời gian định sẵn mới gửi request PUT/PATCH ngầm về server.
FE Q2: Cơ chế PWA Offline hoạt động như thế nào?
Trả lời: Dùng Service Worker bắt sự kiện fetch để cache static assets (HTML/CSS/JS). Dùng IndexedDB lưu note ở client. Khi có mạng (sự kiện online), đồng bộ các thay đổi lên server.
FE Q3: Khi nhiều người cùng sửa note, FE xử lý WebSocket ra sao?
Trả lời: Client lắng nghe event socket từ server khi người khác gõ để cập nhật state editor, đồng thời phát event khi user chỉnh sửa nội dung kèm con trỏ chuột.
BE Q1: Tại sao mỗi note lại có password riêng và lưu trữ như thế nào?
Trả lời: Mỗi note có cột password riêng trong bảng Notes được băm bằng bcrypt. Khi mở note, client gửi pass lên để verify; nếu đúng server mới trả về nội dung giải mã.
BE Q2: AI Q&A hoạt động ra sao để trích dẫn đúng note tham chiếu?
Trả lời: BE lấy các note liên quan của user, đưa vào context prompt gửi cho Gemini API kèm chỉ thị: "Chỉ trả lời dựa trên context và liệt kê ID các note đã sử dụng", sau đó parse ID trả về client.
BE Q3: Khi xóa một nhãn (Label), tại sao các ghi chú không bị xóa?
Trả lời: Thiết kế bảng trung gian note_labels (n-n). Khi xóa nhãn trong bảng labels, chỉ xóa các bản ghi liên kết trong note_labels, bảng notes hoàn toàn giữ nguyên.
